# GitHub Repository Readiness — v0.41.0

This document separates repository files that can be enforced in source from GitHub account/repository settings that must be enabled in the GitHub UI.

## Enforced in this repository

- `.github/workflows/ci.yml` — frozen-lockfile install + repository readiness + full `pnpm check` on `main` and pull requests.
- `.github/workflows/codeql.yml` — JavaScript/TypeScript CodeQL `security-extended` analysis on push, PR and weekly schedule.
- `.github/workflows/dependency-review.yml` — blocks pull requests that introduce known **high** severity vulnerable dependencies.
- `.github/dependabot.yml` — weekly pnpm/npm monorepo updates and GitHub Actions updates.
- `SECURITY.md` — private disclosure guidance and current network/authority posture.
- `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, PR and issue templates — public project hygiene.
- `scripts/verify-repository-readiness.mjs` — checks that the above controls and key secret-file guards remain present.

## Required GitHub settings after push

In **Settings → Security and quality / Advanced Security** for a public repository:

1. Ensure the dependency graph is enabled.
2. Enable Dependabot alerts.
3. Enable Dependabot security updates.
4. Enable private vulnerability reporting.
5. Confirm code scanning accepts the checked-in CodeQL advanced workflow. Do not also enable CodeQL default setup for the same repository unless deliberately switching setup modes.
6. Confirm secret scanning is active; enable repository push protection where the account/repository plan exposes that control.

## Default-branch ruleset

For a solo-maintainer submission repository, protect `main` without creating an unnecessary reviewer bottleneck:

- block force pushes;
- block branch deletion;
- require status checks before merge once the workflows have produced their first checks;
- require **CI / Validate / Node 24 / pnpm 10**;
- require **CodeQL / JavaScript-TypeScript**;
- require **Dependency Review** for pull requests;
- optionally require the branch to be up to date before merge;
- do not require an external approving reviewer while the project has only one maintainer unless a collaborator is available.

## Lockfile

The GitHub default branch must contain the real `pnpm-lock.yaml` generated by the working repository. CI intentionally uses `pnpm install --frozen-lockfile`, so lockfile drift or omission fails closed.

## Repository metadata

Before submission, verify:

- concise GitHub description: `BSC financial-agent marketplace — know what your money needs, spot the right agent for it.`
- website points to the deployed Spotriq frontend;
- topics include relevant terms such as `bnb-chain`, `bsc`, `erc-8004`, `ai-agents`, `defi`, `pancakeswap`, `venus`, `typescript`;
- repository visibility matches submission requirements;
- no production screenshots, links or metrics are claimed unless they exist and are current.
